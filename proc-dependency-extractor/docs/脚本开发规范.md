# 存储过程脚本开发规范（字段级血缘解析适配版）

**适用范围**：proc-dependency-extractor 解析的全部存储过程脚本
**背景**：基于字段级血缘断链修复（744 → 0）过程中沉淀的解析器能力边界，规范脚本写法可确保血缘 100% 正确解析
**日期**：2026-09-02

---

## 一、必须遵守（违反会直接产生断链）

### 1. 裸列必须写表别名前缀

多表 JOIN / 派生表场景下，无前缀裸列的归属依赖"列名唯一匹配"兜底，存在歧义即断链。

```sql
-- 反例（曾导致断链）：int_income 为 JOIN 子查询的聚合输出列，裸列无归属
SELECT sum(int_income) AS int_income
FROM cdm.c_agt_loan_rcpt_inf a
LEFT JOIN (SELECT obj_no, sum(m1.ACC_INT_YEAR * d.DOM_CURRCY_CONVT_PRICE) AS int_income
           FROM fdm.F_EV_FTPS_PUB_CUST_INF m1 ...) c ON ...

-- 正例：显式前缀，解析器直接归属
SELECT sum(c.int_income) AS int_income
FROM cdm.c_agt_loan_rcpt_inf a
LEFT JOIN (SELECT obj_no, sum(m1.ACC_INT_YEAR * d.DOM_CURRCY_CONVT_PRICE) AS int_income
           FROM fdm.F_EV_FTPS_PUB_CUST_INF m1 ...) c ON ...
```

### 2. 子查询必须定义别名

```sql
-- 反例：外层无法用前缀引用（只能靠裸列兜底）
SELECT data_dt FROM (SELECT ... FROM t1)

-- 正例
SELECT t.data_dt FROM (SELECT ... FROM t1) t
```

### 3. 派生表聚合输出列名可追溯

```sql
-- 建议：外层引用名与内层别名显式区分，避免同名穿透歧义
SELECT t.total_int_income          -- 而非 t.int_income 与内层同名
FROM (SELECT sum(a.int_income) AS total_int_income FROM ...) t
```

### 4. 临时表命名遵守 VT_/TMP_ 前缀规则 ⭐

脚本内 `CREATE TABLE`（无 TEMPORARY 关键字）建的表，**仅当表名命中 VT_/TMP_ 前缀规则才被识别为临时表**，否则按物理表处理（影响血缘层级折叠与跳数统计）。

```sql
-- 反例：会被当作物理表，下游引用不折叠
CREATE TABLE {PID}.result_x (DATA_DT DATE, ...);
INSERT INTO {PID}.result_x SELECT ...;

-- 正例：VT_ 前缀，识别为临时表
CREATE TABLE {PID}.VT_result_x (DATA_DT DATE, ...);
INSERT INTO {PID}.VT_result_x SELECT ...;

-- 正例：带 TEMPORARY 关键字时命名自由度更高，但建议仍带前缀（双重保险）
CREATE TEMPORARY TABLE {PID}.tmp_risk_score AS SELECT ...;
```

**命名规则**（任一命中即判临时表）：
- `VT_` 开头
- `TMP_` 开头
- `_TMP` 结尾

**推荐写法**：`CREATE TEMPORARY TABLE` + VT_/TMP_ 前缀双重保险。TEMPORARY 关键字是最无歧义的识别方式；命名规则是 GBase 脚本（无 TEMPORARY 关键字）的兜底，历史脚本大量存在，新脚本不建议依赖。

### 5. 临时表名不加日期占位符后缀；占位符只用花括号形式 ⭐

**临时表名固定**，数据日期用 `DATA_DT` 列承载：

```sql
-- 推荐：临时表名固定，无后缀
CREATE TEMPORARY TABLE {PID}.VT_01 (DATA_DT DATE, CUST_NO VARCHAR(32));
INSERT INTO {PID}.VT_01 SELECT ...;

-- 历史兼容（不建议新脚本使用）：{} 花括号日期后缀
-- 解析时后缀自动剥离、按 VT_01 统一归属，可正确解析
CREATE TABLE {PID}.VT_01_{ETL_TX_DT} (DATA_DT DATE, CUST_NO VARCHAR(32));
INSERT INTO {PID}.VT_01_{ETL_TX_DT} SELECT ...;

-- 反例：${} 形式、字面量后缀均不被识别为占位符，产生断链
CREATE TABLE {PID}.VT_01_${ETL_TX_DT} (...)      -- ${} 不识别
INSERT INTO PID.VT_01_20260818 SELECT ...         -- 字面量后缀不识别
```

> 日期占位符后缀的真实适用场景是**物理分区表**（如 `A_D_FIN_MKT_PRFT_LOSS_DTL_10` 类数字分区），临时表不必使用。

**占位符用法速查**：

| 写法 | 位置 | 解析行为 |
|------|------|---------|
| `{PID}` / `{CDM}` / `{FDM}` | schema 前缀 | 去花括号保留 schema 名：`{PID}.t` → `PID.t` |
| `{ETL_TX_DT}` 等日期占位符 | 表名后缀 | 整段后缀剥离：`VT_01_{ETL_TX_DT}` → `VT_01`（临时表不建议使用，见上） |
| `{ETL_TX_DT}` | 值位置（引号内） | 替换为 `__ph_ETL_TX_DT__` 字面量，常量列不产生断链 |
| `DATE'{ETL_TX_DT}'` | 日期字面量 | 识别为日期字面量（勿与表名后缀混淆，已特判） |

## 二、强烈建议（提高解析准确性）

| # | 规范 | 说明 |
|---|------|------|
| 6 | CTAS 显式写 AS：`CREATE TABLE vt_x AS SELECT ...` | 缺 AS 是 GBase 方言，靠预处理自动补，存在边界风险 |
| 7 | 避免裸 `SELECT *`，显式列出列名 | 裸 * 仅在"FROM 为单一子查询且无 JOIN"时可展开 |
| 8 | 嵌套子查询 ≤ 5 层 | 解包/穿透深度上限为 5 层 |
| 9 | `A.*` 前缀仅用于物理表别名 | 子查询别名前缀星号（`t.*`）要求内层可枚举（无裸 *） |
| 10 | INSERT INTO 临时表显式写目标列清单 | `INSERT INTO vt_x (col1, col2) SELECT ...` 为裸列归属多提供一层依据 |
| 11 | 不出现 2 个以上连续空行 | JSqlParser 4.9 解析 JOIN 链会中断（已预处理，源头规范更稳） |
| 12 | 日期字面量占位符与 DATE 间保留空格 | `DATE '{ETL_TX_DT}'` 优于 `DATE'{ETL_TX_DT}'`（后者靠特判支持） |

**SELECT * 示例**：

```sql
-- 可解析：FROM 为单一子查询、无 JOIN，裸 * 展开为内层输出列
CREATE TABLE {PID}.VT_A SELECT * FROM (
    SELECT DATE '{ETL_TX_DT}' AS data_dt, t1.cust_no FROM cdm.t1
) t;

-- 不可解析（断链）：多表 JOIN 的裸 * 无法归属
SELECT * FROM a JOIN b ON a.id = b.id;

-- 正例：显式列名
SELECT a.id, b.name FROM a JOIN b ON a.id = b.id;
```

## 三、方言约束（依赖预处理的宽容项，尽量避免）

| # | 规范 | 替代方案 |
|---|------|---------|
| 13 | 不使用 `EXCEPT ALL` | 用 `EXCEPT` 或 `NOT IN` |
| 14 | 不写 `TABLESPACE='xxx'` 私有表选项 | 无 |
| 15 | `CREATE TEMPORARY TABLE` 关键字间只用单空格 | - |

## 四、元数据侧要求（新表上线流程）

- **DWA 自产表必须同步补录 columns0818.xlsx**：新建中间产出表若不进元数据，下游 proc 引用其裸列时唯一匹配失败（案例：`a_g_agt_org_report_dtl` 曾因此产生 2 条断链）
- **日期分区表命名遵守 `基表名_数字后缀`**：如 `xxx_dtl_10`，元数据只需录基表，分区表自动回退基表列集合

```sql

-- 分区表 _10/_11/... 无记录时自动回退基表列

```

## 五、完整正例模板

```sql
-- 1. 建临时表：TEMPORARY 关键字（最无歧义）+ VT_ 前缀（双重保险）+ 显式列定义
--    注意：临时表名不加日期占位符后缀（如 _{ETL_TX_DT}），见第 5 条
CREATE TEMPORARY TABLE {PID}.VT_demo_01 (
    DATA_DT      DATE,           -- 数据日期
    CUST_NO      VARCHAR(32),    -- 客户号
    INT_INCOME   DECIMAL(20,2)   -- 利息收入
);

-- 2. 装载：显式目标列清单 + 全部列带前缀 + 子查询有别名
INSERT INTO {PID}.VT_demo_01 (DATA_DT, CUST_NO, INT_INCOME)
SELECT DATE '{ETL_TX_DT}',
       a.CUST_NO,
       sum(c.ACC_INT_YEAR * d.DOM_CURRCY_CONVT_PRICE)
FROM cdm.c_agt_loan_rcpt_inf a
LEFT JOIN (SELECT t1.OBJ_NO, sum(t2.AMT) AS ACC_INT_YEAR
           FROM fdm.f_ev_ftps_pub_cust_inf t1
           JOIN fdm.c_com_exch_rate t2 ON t1.CCY = t2.CCY
           GROUP BY t1.OBJ_NO) c ON a.OBJ_NO = c.OBJ_NO
LEFT JOIN fdm.c_com_exch_rate d ON a.CCY = d.CCY
GROUP BY a.CUST_NO;

-- 3. 产出：物化到目标表（无 VT_ 前缀 = 物理表，正常产出节点）
INSERT INTO {PID}.A_G_DEMO_SUM (DATA_DT, CUST_NO, INT_INCOME)
SELECT t.DATA_DT, t.CUST_NO, t.INT_INCOME
FROM (SELECT DATA_DT, CUST_NO, INT_INCOME FROM {PID}.VT_demo_01) t;
```
